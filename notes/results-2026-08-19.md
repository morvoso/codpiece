All numbers from llm-host, inside locked bench windows (prod stopped,
thermal watchdog, prod restored + health-verified after every run).
Peak GPU temperature across ~17 windows: 46 °C. Prod never disturbed.

## Speed — Qwen3.8-27B Q8_K_XL, both 3090s, TENSOR PARALLEL

The headline number. Same model, same GPUs, same flags family:

| engine | decode tok/s | output |
|---|---|---|
| **tandem, `--tp 0,1`** | **39.8** (39.88 / 39.74 / 39.69) | **identical to llama.cpp** |
| llama.cpp b10423, `-sm tensor -ts 50,50 -fa on` | 41.4 (41.45 / 41.34) | reference |

tandem is at **96 %** of production llama.cpp on the real model, and
**2.1× faster than its own layer-split path** (19.0 → 39.8). Neither engine
has MTP speculative decoding enabled here; prod's ~50 tok/s figure includes
it, and it is tandem's M4.

Prefill and depth, tensor parallel:

|---|---|
| prefill, 7,521-token prompt | **1,494 tok/s** (ENGINE.md's prod baseline: 1,387 @ 27K) |

## Speed — Qwen3.8-27B Q8_K_XL, both 3090s, layer split (superseded)

| | |
|---|---|
| weights placed | 16.57 GiB (GPU0) + 12.72 GiB (GPU1) |
| prefill | 105 tok/s (oracle `-sm layer`: 147) |
| decode | 19.0 tok/s (oracle `-sm layer`: 26.4 — tandem at 72 %) |
| output vs oracle | identical (sha256 match) |

Prod's deployed config reaches ~50 tok/s using tensor split + MTP
speculative decoding, neither of which tandem has yet — that is M3e and M4,
not a like-for-like comparison with the number above.

Layer split is the *correctness* path, not the fast one: the scheduler
re-plans every step, the cached decode graph is disabled, and all session
KV/state sits on device 0. Tensor parallel (M3e) is what prod's `-sm tensor`
uses and what closes this gap.

## Bugs found, and what found them

| bug | found by | why it was invisible before |
|---|---|---|
| all-f32 KV caches corrupt on CUDA | GPU self-test | CPU kernels are fine; only CUDA's V transposed-write/padded-read path breaks |
| device-side mask never initialized | GPU self-test | CPU's synchronous fallback masked it |
| graph inputs treated as persistent across computes | 2,334-token parity run | allocator only overlapped the input at large n_kv |
| `GGML_CUDA_GRAPHS` off by default in standalone ggml | A/B with `GGML_CUDA_DISABLE_GRAPHS` | debug logs are compiled out; the logits copy hid the effect |
| scheduler needs a CPU backend last | 2-GPU run | documented only as an assert |
